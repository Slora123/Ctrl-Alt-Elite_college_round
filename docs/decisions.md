# Decisions and deferred items

## Decided

- **D-01 (P1) Location.** The P1 code lives in `core/` (package `crisisgrid_core`), a pure-Python project with no persistence, web or LLM imports (enforced by `core/tests/test_architecture.py`). The Node/Express website backend is kept as is for now; migrating it to the Python API is deferred to P4+.
- **D-03 (P1) Interactive runs are rejected, not filtered.** `verify_claim` raises `IneligibleRunError` if any offered `RunResult` is not a clean, verification-eligible run. `RunResult` itself refuses `verification_eligible=True` with `mode="interactive"`. The pseudo-code in system_design 5.2 filters silently; raising is stricter so caller bugs surface.
- **D-04 (P1) Claim comparison is in the claim's own unit.** The verifier compares `metrics[claim.metric]` to `reported_value` and `tolerance` directly. Percent vs fraction conversion is not guessed; a unit mismatch is the Audit rules' job (R-series) and reaches the verifier as `metric_mismatch` (verdict `inconclusive`).
- **D-05 (P1) Hashing.** Floats with integral values fold to ints (`1.0 == 1`); NaN/inf in a spec is an error. A bound cell's code is hashed via `ast.dump` (comments/whitespace ignored), with a comment/whitespace-stripping fallback for source containing notebook magics.
- **D-06 (P1) Edited-node provenance.** `create_version` sets edited nodes to `human` (author human) or `inferred` (author agent), per the Author-to-Provenance mapping.

## Deferred

- **D-02 Reconcile Paper Environment models.** `core.models` implements system_design 1.1 as written. `paper_env/paper_env/domain/models.py` already has local versions with extra fields (e.g. `Run`, `CellRun.blocked_action_id`, `Checkpoint.cell_versions`) and different shapes. They are not merged yet; decide in P5/P6 which is canonical and whether `paper_env` imports from `core`.
- **D-07 Attribution, Audit rules, Harness guard firewall test.** Not in P1. The firewall test lands with the first agent (P3).
- **D-08 `paper_env` persistence.** `paper_env` still uses `uuid4` hex IDs and SQLite; moving it to `uuid7` and the shared Postgres is deferred to the P5/P6 reconciliation (see D-02).
- **D-09 Rest of the monorepo skeleton.** P0 added `api/` (plumbing + FastAPI health) next to `core/` and `paper_env/`. `orchestration/`, `agents/`, `gateway/`, `worker/` are created in the phase that first needs them (P3, P4, P6) rather than as empty directories.
- **D-10 CI covers `core` and `api` only.** `paper_env` tests need `uv`, a jupyter kernel and network, and are not run in CI yet.
- **D-11 Docker Compose is untested.** `docker-compose.yml`, `api/Dockerfile` and the Postgres/pgvector branch of migration 0001 were written without Docker or Postgres available. Migration and health logic are tested on SQLite only. First thing to do when Docker is available: `docker compose up --build` and `curl localhost:8000/health` (expect `{"status":"ok","db":"ok","migration":"0002"}`).
- **D-12 Redis and MinIO are in Compose but unused** until P4 (streams/SSE) and P5/P6 (outputs, artifacts).
- **D-13 Package placement.** Instead of one top-level directory per plan component, pure logic lives in `core/` (Harness guard, later audit rules, route selector, verifier) and infrastructure-facing modules live in `api/crisisgrid_api/` as subpackages (`gateway/`, later `agents/`, `orchestration/`, `worker/`). Split into separate deployables when a process boundary actually exists (the worker, P6).
- **D-14 LLM access is behind `ModelClient`.** No provider keys were available, so tests use `ScriptedClient`. `gateway/litellm_client.py` (Qwen on Groq/Ollama, BYO keys) is written but has never been run against a real provider. Verify before relying on it.
- **D-15 Agents use a thin typed-output wrapper, not Pydantic AI.** `gateway/structured.run_structured` validates JSON against a Pydantic model with one guarded retry. Pydantic AI / pydantic-graph APIs change quickly and could not be checked against current docs here; swapping them in later only touches `gateway/` and `orchestration/`.
- **D-16 (P2) Audit rules R01-R11 are my definitions.** system_design.md only specifies R12-R16 ("R01 to R11 unchanged from v1", which was not provided). I defined: R01 seed, R02 hyperparameters (learning_rate, batch_size, epochs, optimizer), R03 split definition/provenance, R04 metric ambiguity (top-1/top-5, micro/macro), R05 compute, R06 code availability, R07 dataset availability (the only rule that emits `blocking`: private data), R08 dependency pinning, R09 variance/single run, R10 preprocessing, R11 pretrained weights. R06/R07/R15 map to the "Artifact Verification" page as in section 10. Replace with the v1 definitions if they differ. Text rules (R10-R14, R16) are regex heuristics that quote their evidence; they flag, never decide.
- **D-17 (P2) Embeddings are not in pgvector yet.** `ingest/embed.py` has an `Embedder` protocol, a deterministic hashing embedder and an in-memory index (used for context selection). A pgvector table and a real embedding provider (hosted vs local, open decision #5) are deferred; the migration already enables the `vector` extension on Postgres.
- **D-18 (P2) Gold-labelled parse evals not done.** Needs 3 real papers with hand-labelled values and a real model. The quote-verification step (`enforce_sources`) is the safety net in the meantime and is unit-tested. OCR fallback is a hook (`ocr=` callable); no OCR engine is bundled, a scanned PDF returns `needs_ocr=True`.
- **D-19 (P2) Artifact finder is rule-based, not an LLM agent,** and the GitHub adapter was tested against a mock transport only. Never run against the live API.
